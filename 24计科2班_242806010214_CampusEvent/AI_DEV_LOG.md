## 二、关键设计决策：Q-01～Q-10（2026-11-22）

> 决策人：学生；AI 仅提供问题、选项与影响分析。以下为学生的判断与理由，用于满足“关键设计决策与人工判断”记录要求。

| 编号 | 问题 | 学生决策 | 学生理由 |
|---|---|---|---|
| Q-01 | “符合基本条件”包含哪些校验 | 活动未开始 + 无重复有效报名 + 名额充足 + 活动未被删除/取消 | 基本条件应包含这些信息，方便用户使用 |
| Q-02 | 满员时能否提交审核型报名 | 允许提交为“待审核”，名额释放后再审批 | 可能有人取消而空出名额 |
| Q-03 | 活动开始后能否取消报名 | 只允许取消“待审核” | 避免脏数据、假数据 |
| Q-04 | 通知失败的事务边界 | 报名与通知同一事务；通知失败报名整体失败并提示 | 强一致性优先，通知是报名生效的必要告知环节 |
| Q-05 | 并发审批 / 重复提交防超卖 | 事务 + 条件更新 + 唯一约束 + 失败重试 | 条件更新防超卖、唯一索引防重复，兼顾性能与可靠性 |
| Q-06 | 删除活动策略 | 软删除，报名与消息保留 | 容错性高、支持数据恢复 |
| Q-07 | 名额检查位置 | 公共流程 CapacityChecker（原 C 修正为 A） | 公共不变量集中，避免策略重复检查 |
| Q-08 | 3.2 补充功能是否纳入 | 纳入（活动创建/编辑、按名称筛选、统计） | 3.2 功能同属需求部分 |
| Q-09 | 状态迁移表 | 确认提议的迁移表 | 简洁、实现成本低、稳定 |
| Q-10 | 学生查看剩余名额的建模 | 并入“浏览活动”详情展示，不新增用例；只显示剩余名额 | 保持用例图简洁 |

> Q-07 于 2026-11-22 类图方案对比后由 C 修正为 A（CapacityChecker 公共名额检查）；原理由“兼顾复用性与灵活性”被“策略重复检查”的成本取代，详见 docs/05-类图方案对比.md。
