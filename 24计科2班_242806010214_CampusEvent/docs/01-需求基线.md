## 1. 术语

| 术语 | 定义 | 依据 |
|---|---|---|
| 直接报名型 | 报名即通过的活动（Activity.policy_type 为直接报名） | B.1 Activity、B.2-1 |
| 审核型 | 报名需管理员批准或拒绝的活动 | B.1 Activity、B.2-2 |
| 有效报名 | 状态为“待审核”或“已通过”的报名 | B.2-4 |
| 剩余名额 | Activity.capacity 减去该活动“已通过”报名数 | B.2-3 |
| 站内消息 | 写入 Message 表、供学生查看的通知记录 | B.1 Message |

## 2. 角色（B.1）

| 角色 | 能做什么 | 约束 |
|---|---|---|
| Student（学生） | 浏览活动、报名、取消自己的报名、查看站内消息 | 固定演示账号 |
| Admin（管理员） | 审批报名（批准/拒绝）、删除活动；创建/编辑活动见补充需求 REQ-20 | 固定演示账号 |

不做：用户注册、登录鉴权、复杂权限体系（B.1 原文“无需用户注册和复杂权限系统”）。

## 3. 领域对象（B.1 表格，4 个）

| 对象 | 主要字段 | 约束 |
|---|---|---|
| Student | student_id、name | student_id 唯一 |
| Activity | activity_id、title、category、start_at、location、capacity、policy_type | capacity 为正整数；活动开始前允许报名 |
| Registration | registration_id、activity_id、student_id、status、created_at、updated_at | status 仅限 待审核 / 已通过 / 已拒绝 / 已取消 |
| Message | message_id、student_id、activity_id、content、created_at、is_read | 报名或审核动作可产生站内消息 |

对象间关联（Student—Registration—Activity、Message 关联 Student/Activity）在类图中定稿，本文件不预设多重性与导航性。

| REQ-09 | 管理员可批准或拒绝“待审核”报名；批准前必须再次检查剩余名额。 | B.2-2 | C6、C7、C8 |

| REQ-19 | 删除已有报名的活动采用“软删除”：活动对用户隐藏，报名与消息保留（Q-06）。 | B.2-7 | 边界（Q-06） |

## 5. 业务规则与 REQ 对照（B.2）

| 规则 | 原文要点 | 对应 REQ |
|---|---|---|
| B.2-1 | 直接报名活动名额充足且符合基本条件→“已通过”，并产生站内通知 | REQ-06、REQ-07 |
| B.2-2 | 审核型提交→“待审核”，管理员批准/拒绝；批准时再次检查剩余名额 | REQ-08、REQ-09、REQ-10 |
| B.2-3 | 名额按“已通过”统计，待审核不占；满员后不得再批准 | REQ-11、REQ-12 |
| B.2-4 | 同一学生同一活动不得有两条待审核/已通过；已取消、已拒绝留历史，可再申请 | REQ-13、REQ-14 |
| B.2-5 | 学生可取消自己的待审核/已通过报名；活动开始后不允许新增报名 | REQ-15、REQ-16 |
| B.2-6 | 通知失败留痕，不得让合法报名无声消失；事务边界由学生设计并解释（Q-04：同事务，失败整体回滚） | REQ-17 |
| B.2-7 | 活动与报名持久化；删除有报名的活动二选一（Q-06：软删除） | REQ-18、REQ-19 |

## 9. 已定设计决策（Q-01～Q-10，2026-11-22）

| 编号 | 决策 | 学生理由（摘要） |
|---|---|---|
| Q-01 | 基本条件 = 活动未开始 + 无重复有效报名 + 名额充足 + 活动未被删除/取消 | 便于用户判断活动是否可用 |
| Q-02 | 满员时仍允许提交审核型报名，待名额释放后再审批 | 可能有人取消，空出名额 |
| Q-03 | 活动开始后只允许取消“待审核”报名 | 避免脏数据、假数据 |
| Q-04 | 报名与通知同一事务、强一致；通知失败报名整体失败并提示 | 通知是报名生效的必要告知环节 |
| Q-05 | 数据库事务 + 条件更新 + 唯一约束 + 失败重试 | 条件更新防超卖，唯一索引防重复 |
| Q-06 | 删除活动采用软删除，报名与消息保留 | 容错性高、支持恢复 |
| Q-07 | 名额检查放公共流程（CapacityChecker），策略只决定结果（原 C 修正为 A） | 公共不变量集中，避免策略重复检查 |
| Q-08 | 纳入指导书 3.2 的 REQ-20～REQ-22 | 3.2 同属需求范围 |
| Q-09 | 确认状态迁移表 | 简洁、实现成本低、稳定 |
| Q-10 | 学生剩余名额并入“浏览活动”详情，不新增用例；只显示剩余名额 | 保持用例图简洁 |

详细背景与学生理由见 [03-待决策边界问题.md](03-待决策边界问题.md) 与 [AI_DEV_LOG.md](../AI_DEV_LOG.md)。
