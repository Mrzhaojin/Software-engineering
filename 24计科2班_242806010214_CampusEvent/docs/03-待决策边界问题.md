## Q-01 “符合基本条件”包含哪些校验？（B.2-1）

- **决定：B。** 活动未开始 + 无重复有效报名 + 名额充足 + 活动未被删除、未取消。
- **学生理由：** 活动基本条件应该包含这些信息，方便用户进行使用。
- 影响：报名入口校验、错误提示、C2/C4 测试步骤。

## Q-02 满员时，审核型活动能否提交报名？（B.2-2、B.2-3）

- **决定：A。** 允许提交为“待审核”，等名额释放后再审批。
- **学生理由：** 满员时活动可能尚未开始，可能出现取消报名而空出名额，此时可把名额给已提交“待审核”的用户。
- 影响：待审核不占名额的边界、审批队列、C4/C8、错误提示。

## Q-03 活动开始后，能否取消已有报名？（B.2-5）

- **决定：C。** 只允许取消“待审核”报名。
- **学生理由：** 以免造成用户报名的脏数据、假数据等。
- 影响：状态迁移表、取消入口、C9、统计同步。

## Q-04 通知失败时的事务边界怎么定？（B.2-6）

- **决定：A。** 报名与通知同一事务：通知失败则报名整体失败并提示（不存在“已提交报名”）。
- **学生理由：** 属于强一致性优先的设计，更适合“通知是报名生效的必要告知环节”的定位。
- 影响：数据库事务设计、失败留痕（事务外日志）、C2/C6/C7 证据、B.2-6 合规说明。

## Q-05 并发审批 / 重复提交如何防超卖？（B.2-2、B.2-3）

- **决定：A + D。** 数据库事务 + 条件更新（满足容量条件才更新）+ 唯一约束 + 失败重试。
- **学生理由：** 条件更新控制总名额防超卖，唯一索引兜底防重复提交，二者兼顾性能与可靠性。
- 影响：C8 可复现性、并发测试设计、实现复杂度。

## Q-06 删除活动采用哪种策略？（B.2-7 明确二选一）

- **决定：B。** 软删除：活动对用户隐藏，报名与消息保留。
- **学生理由：** 容错性高，支持数据恢复。
- 影响：列表/筛选/统计过滤、数据一致性、C10。

## Q-07 名额检查放在哪一层？（指导书 3.3 设计任务 B）

- **决定：C。** 服务前置检查 + 策略内兜底。
- **学生理由：** 平衡复用性与灵活性，业务演进平滑。
- 影响：避免新增策略重复实现，同时保留策略自治；D-03 论证材料。

## Q-08 附件 B 未覆盖的 3.2 功能是否纳入本版基线？

- **决定：A。** 纳入：REQ-20 活动创建/编辑、REQ-21 按名称筛选、REQ-22 统计。
- **学生理由：** 3.2 中的功能同样属于需求部分。
- 影响：C1 使用真实创建流程；初始功能覆盖评分。

## Q-09 状态迁移表是否按提议确认？（B.1 状态集、B.2-4、B.2-5）

- **决定：确认。** 迁移如下：
  - 待审核 → 已通过 / 已拒绝 / 已取消
  - 已通过 → 已取消
  - 已拒绝、已取消为终态
  - 重新申请时新建一条报名记录，不复用旧记录
- **学生理由：** 状态机设计简洁，实现成本低且稳定性强。
- 影响：status 字段实现、C3/C9、重复报名判定。
