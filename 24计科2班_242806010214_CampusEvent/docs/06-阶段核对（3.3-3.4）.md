## 3. Git 标签 baseline-v1 任务确认

- **定义（3.4）**：完成初始功能、自动化测试和版本封存后，打 Git 标签 baseline-v1。
- **现在不能打**：仓库里还没有实验二代码与自动测试；提前打标签会产生“空标签”，3.8 要求的“两版源代码/标签”对照会失效。
- **正确顺序**：类图/时序图/设计原则 → 学生评审签名 → AI 编码 → C1–C10 功能验收 + pytest → 版本封存 → git tag baseline-v1 → 等教师 CR。
- **CR 之后（3.6）**：从 baseline-v1 建新分支修改，保留 Git 差异与 AI 交互记录；回归全部 C1–C10 + 新增用例；完成后打 change-v2。
- **3.8 提交要求**：必须部署云服务器；提交两版源码/标签、初版与变更版类图、回归测试表、变更影响分析、AI_DEV_LOG、项目总结（5–8 页）。
- **3.7 可维护性**：最终统计新增类数、修改的核心业务类数、回归失败数、AI 交互轮次、修改总时长。
