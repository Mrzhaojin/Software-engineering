# StudyTask · 个人学习任务管理系统

> 《软件工程》实验一 ｜ 24 计科 2 班 · 242806010214 ｜ 项目代号：StudyTask
> 状态：初版已实现，等待人工验收（T1–T10 实测记录见 [`docs/验收记录.md`](docs/验收记录.md)）

## 1. 项目概述

单用户、本地运行的 Web 应用，用于记录课程作业、实验、考试准备等学习任务。目标用户为单个在校大学生，数据保存在本地 SQLite 数据库中。需求来源：实验指导书附录 A《StudyTask 需求规格说明书》。

## 2. 功能范围

| 编号 | 功能 | 验收重点 |
| --- | --- | --- |
| P1-F01 | 新建任务（名称、课程、描述、截止日期、优先级） | 必填项校验，正确保存 |
| P1-F02 | 查看、编辑、删除任务 | 操作结果可见，删除须二次确认 |
| P1-F03 | 任务状态：待完成 / 进行中 / 已完成 | 变更后持久保存 |
| P1-F04 | 按课程、状态、优先级筛选 | 筛选结果准确，支持组合条件 |
| P1-F05 | 按截止日期识别逾期与即将到期 | 日期逻辑正确 |
| P1-F06 | 统计总数、完成数与完成率 | 统计结果正确，0 条时为 0% |
| P1-F07 | 本地持久化 | 重启服务后数据仍存在 |

**范围外**（附录 A.5 明确不做）：账号注册与多用户权限、共享任务、邮件/短信推送、第三方日历同步、移动端 App、云部署。

## 3. 技术方案

- 后端：Python 3.13 + Flask 3.1（Flask 内置开发服务器，本地单用户使用）
- 数据库：SQLite（首次启动自动创建 `studytask.db` 并建表）
- 前端：Jinja2 模板 + 原生 HTML / CSS / JS（未引入前端框架）
- 测试：pytest（20 条自动化测试）

### 3.1 路由

| 路由 | 方法 | 说明 |
| --- | --- | --- |
| `/` | GET | 任务列表：组合筛选、统计、逾期 / 即将到期提示 |
| `/tasks/new` | GET / POST | 新建任务表单与提交 |
| `/tasks/<id>` | GET | 任务详情、状态调整入口、删除入口 |
| `/tasks/<id>/edit` | GET / POST | 编辑任务各字段 |
| `/tasks/<id>/delete` | POST | 删除任务（页面二次确认） |
| `/tasks/<id>/status` | POST | 调整任务状态 |

### 3.2 数据库结构

`schema.sql` 定义 `tasks` 表：`id`、`name`、`course`、`description`、`due_date`、`priority`、`status`、`created_at`、`updated_at`；并为 `course`、`status`、`priority`、`due_date` 建立索引。

> 实验一允许 AI 自主设计内部类与表结构；本实现为单模块 Flask 应用 + 模板，未引入额外框架。

## 9. 已知限制

1. 删除的二次确认依赖浏览器 `confirm()`；禁用 JavaScript 时不会弹出确认框（SRS 未要求服务端确认令牌）。
2. 列表不分页，任务很多时页面会较长；SRS 约定 200 条以内正常使用。
3. 完成率按四舍五入取整百分比（如 1/3 显示 33%）。
4. 逾期 / 即将到期以服务器本地日期判断；“未来 3 天”含今天与第 3 天。
5. 日期校验使用 `datetime.strptime`，会接受未补零写法（如 2026-1-1）；页面日期控件默认输出 YYYY-MM-DD。
6. 未实现登录、权限与 CSRF 防护——本地单用户使用，且不在 SRS 范围内。
